# MarkToast 产品定位

> v0 · 已定稿（2026-11-04）。变更需在本文末尾追加决策记录。

## 一句话

**MarkToast 是 agent 记忆的仓库与工作台：任何 coding agent 共用一份 Markdown 记忆，
Git 管版本，本地跑，中文优先。**

## 用户与场景

| 维度 | 定义 |
|---|---|
| 核心用户 | 同时使用 3 个以上 coding agent 的重度开发者（ZCode / Hermes / DSH / Codex / Claude Code / Pi…） |
| 次核心 | 需要共享记忆的小团队；中文开发者社区 |
| 典型场景 | 上午用 ZCode 改 feedsieve，下午换 Codex 继续；三天后想不起某个决定——记忆必须跟人走，不跟工具走 |
| 反例（不服务） | 只用单一 agent 的普通用户；需要云端记忆 API 的应用开发者；模型路由/网关需求（那是 Magpie 的领域） |

## 要解决的问题

1. **记忆被工具绑架**：每家 harness 各存各的格式，换工具就丢上下文。
2. **不可审计**：记忆是黑盒，改了什么、谁改的、能不能回滚，都说不清。
3. **不可迁移**：换机器/换 harness 要重新教一遍。
4. **中文不友好**：检索按英文/空格设计，中文查询命中差。

## 定位与竞争位

MarkToast 不是"又一个记忆引擎"，而是**记忆的客户端 + Git 工作流 + 适配器层**。

| 玩家 | 他们做什么 | MarkToast 的不同 |
|---|---|---|
| ai-memory（15k★） | 记忆引擎：捕获/整理/检索，Markdown+Git 存储 | 它有引擎无产品：没有桌面/审阅 UI；MarkToast 复用其思想，做"工作台" |
| EverOS（13.8k★） | 本地 Markdown 记忆 + 插件（DSH/Hermes） | 无 ZCode、无 Git 工作流；MarkToast 覆盖本地三栈 + Git 审阅 |
| Memsearch（Zilliz） | 语义检索层 | 工具式、无版本/审阅；MarkToast 以 Markdown/Git 为主 |
| claude-mem（112k★） | 会话捕获/压缩，云+本地 | 捕获导向、非 Git 工作流；MarkToast 不追会话压缩，追"可审阅的长期记忆" |
| Magpie（29k★） | 模型网关/路由（Go+Wails） | 领域不同，但**工程与产品形态是 MarkToast 的参照** |
| Mem0 / Honcho / Zep | 云端记忆 API | 不是竞品：MarkToast 本地优先、无云依赖 |

## 差异化（只打三条）

1. **Git 是一等公民**：每次记忆变更是可 diff 的 commit；分支是记忆实验；回滚是 `git revert`；
   审阅/审计是默认流程，而不是"支持 git"。
2. **一份真源 + 原生适配器**：MarkToast 仓库是唯一真源；适配器把索引投影进各家 native
   注入点（ZCode 指令文件、Hermes provider、DSH plugin、MCP/AGENTS.md），并把现有记忆导入。
3. **本地优先 + 中文优先**：零云、零遥测；CJK 分词/子串检索是一等公民。

## 非目标（明确不做）

- 模型网关 / 账号路由 / 计费（Magpie 的领域）
- 云端记忆服务 / SaaS（v1 不做）
- embedding 优先的重记忆引擎（向量仅作可选派生层）
- 首发即跨平台（macOS 优先，Windows/Linux 后续）

## 成功指标（v0.1）

- 作者本人每天使用，连续 7 天不中断
- ZCode / Hermes / DSH 三家读到同一份记忆
- 迁移现有 500+ 条记忆零丢失
- hub 停止时记忆仍可读（降级验证通过）
- 开源首月：200★、10 个真实外部用户反馈

## 商业化（以后，不在 v0.1 范围）

开源核心（MIT）+ 团队版：共享记忆仓库、权限、审计、托管 Git 同步。
个人版不收费；不卖云记忆 API。

## 品牌

- 名字：**MarkToast / 马克吐司**（Mark + Toast；中文致敬马克·吐温）
- 语气：克制、可审计、不炫技；说人话，给证据，不堆形容词。
- 对用户承诺：**你的记忆是一个你拥有的仓库，任何 agent 都只是它的读者和作者之一。**
